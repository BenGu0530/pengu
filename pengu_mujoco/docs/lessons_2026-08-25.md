# Lessons — everything except the RL arm (2026-08-14 → 08-25)

Wrap-up of the non-RL work on machine D: the model pipeline, the shared-machine
setup, the GRID-4 sweep and analysis, and the process failures worth not
repeating. RL findings are deliberately out of scope; they live in
`rl_session_2026-08-21*.md`, `rl_open_concerns.md`, `reward_audit_c6.md` and
`rl_grid4/overnight/JOURNAL.md`.

Each entry is what happened, what it cost, and what changed because of it.

## 1. Model pipeline — Onshape → URDF → MuJoCo

Converted with `onshape-to-robot` 1.8.2 inside the `pengu_sim` conda env. Three
COM variants were converted and **all kept**, none overwritten:

```
models/pengu1_05/{robot.urdf, robot.xml}
models/pengu1_20/{robot.urdf, robot.xml}
models/pengu1_31/{robot.urdf, robot.xml}
```

**Credentials.** The Onshape API keys live in `ben_pengu/.env`, mode `600`,
**one directory above the repo root**. `onshape-to-robot` finds it through
`find_dotenv(usecwd=True)`, which walks upward, so the tool sees it and the
repository cannot.

Lesson: `.gitignore` is a policy that a `git add -f` overrides. Directory
placement is a guarantee. For secrets, use the guarantee.

**Meshes were opened in a viewer before anything downstream used them.** A
conversion that exits 0 is not a conversion that produced the right geometry.

## 2. Shared lab account

`rml2` is shared. The default `github.com` SSH entry belongs to another user, so
the fix was to add a **parallel alias** rather than edit the existing entry:

```
Host github-ben
  HostName github.com
  User git
  IdentityFile ~/.ssh/id_ed25519_ben
  IdentitiesOnly yes
```

Remote: `git@github-ben:robomechanics/pengu.git`.

Lesson: on a shared account, never modify an existing config entry — add one
beside it. The other user's workflow must keep working while you are not
watching it.

The same applies to compute. Another user's training job runs on this machine;
concurrency was held below saturation rather than taking all 16 cores.

## 3. Branch discipline — cost: one wrong push

Commits went to `ben/physics-id-and-sweep` because the branch was inferred from
whatever `HEAD` pointed at. They had to be moved and the stray remote branch
deleted.

Now **CLAUDE.md rule 7**: confirm the branch before pushing; the working branch
is `friction-experiments`. And **rule 6**: no AI attribution in commits, PRs,
comments or docs — verified before each push with
`git log -1 --format='%an %ae'` plus a trailer grep, not by intention.

## 4. Analysis lessons — the ones that changed a conclusion

### 4a. When a table has a selection step, the selection *is* part of the measurement

The apparent "high-friction collapse" in the GRID-4 table was an artifact. The
top-20 gaits had been selected at μ=0.1 and then re-scored at every μ. Giving
each μ its own top-20 — the **diagonal** — moved pass from `0.00` to
`0.85–1.00`.

This is recorded at the top of the report so it cannot be missed
(`results/grid4_report/INDEX.md:31`):

> Use the **diagonal** files (`finalists_mu<XX>.csv`) for any cross-friction
> comparison. `finalists.csv` is the μ=0.1 selection and is correct only at μ=0.1.

Biggest single analysis lesson of the whole engagement: a cross-condition
comparison built on a single-condition selection measures the selection.

### 4b. A column named `valid` is not the map's `pass`

`valid` is a stepping gate (`≥2 steps/leg AND single_frac ≥ 0.3`). I read it as
the pass criterion and published an inverted c1 conclusion, then had to correct
and re-push.

Lesson: check what a column means **in the code that writes it**, not what its
name suggests. CLAUDE.md already carries the sibling trap — `single_frac` is
column 14 — for the same reason.

### 4c. A scalar can hide the behaviour

"Nothing moves forward at μ=0.7" turned out to be walking in circles:

```
steps            70
path length      5.7432 m
net displacement 0.6100 m
straightness     0.107          <- net/path, ~0 = looping
```

Net displacement alone said "stationary". The path integral said "looping" —
a completely different failure with a completely different fix.

Lesson: when a summary statistic says nothing happened, integrate the path
before believing it.

### 4d. RMS algebra — RMS cannot separate a waddle from a lean

`RMS² = mean² + var`, so a ±30° oscillation and a held 30° lean produce the same
RMS. Taking `diff(RMS)` does not fix it either — the derivative of a summary is
still a summary. `RMS(diff)`, the **rate**, does.

This is why `torso_roll_mean_deg` and `torso_roll_rate_rms_dps` exist as
separate columns, and why a reference pair was measured to calibrate them: a
zero-action standing episode gives `|mean|/RMS = 0.992` at 1.2 deg/s; a
random-action episode gives `0.153` at 80–97 deg/s.

### 4e. Look at the artifact, not only the table

The clearest false positive of the engagement read as the best result of the
night in every summary column — high roll RMS, high follow coefficient — and was
a body parked at −47° and held there. The per-trial columns showed `|mean| = RMS`
to four figures and a rate at the standing reference; three frames sampled at
t = 3/6/9 s were the same pose three times.

Lesson: for anything with a shape, render it and look. Summary columns are
designed to be comparable, which is exactly what makes them able to agree with
each other while all being wrong about the same thing.

## 5. Process failures and the fix each one forced

### 5a. Never edit a running bash script — cost 18.5 h

Bash reads a script **incrementally, by byte offset**. Editing
`overnight/run_gen.sh` while it was executing sent the interpreter to a wrong
offset; the parent shell died and its training subshells took `SIGHUP` with it.

Signature to recognise: logs stop cleanly mid-line with **no traceback**, and
`dmesg` shows **no OOM**.

Fix: generations run only from frozen versioned copies (`run_gen_v2.sh` …
`run_gen_v5.sh`), never touched while a queue is live; changes go into a new
copy.

Contrast worth knowing: editing a `.py` mid-run **is** safe. Python compiles the
whole file at import and closes the handle, so a running process is unaffected.

### 5b. A sync destroyed uncommitted data

While resolving a path collision after a pull, `git checkout HEAD -- runs/archive/…`
overwrote a local uncommitted `diag.csv`, losing 22 of 24 rows. They were
recovered from a stdout log that happened to carry the same rows — luck, not
method.

Fleet rules adopted (`grid4_fleet_memo.md`):
1. `runs/` layout changes are announced in a memo **before** pushing, and other
   machines commit local run data before pulling.
2. Every run tees stdout to a committed `.log`, so rows stay recoverable.

Root cause worth stating plainly: run outputs live in gitignored paths and enter
the repo only via `git add -f`, so one machine reorganising a directory while
another writes into the old layout can silently destroy the second machine's data.

### 5c. A fallback that cannot be distinguished from success is a bug

A selection step printed a **label** (`best=2000k`) and the script fed it
straight to `[ -f "$ck" ]`, which can never match a path. It silently fell back
to the last checkpoint — for four generations, while printing nothing wrong.

Fix: map label → path explicitly, and **warn loudly** when falling back.

Lesson: a silent fallback converts a broken step into a plausible number. Every
fallback path needs a distinguishable signal.

### 5d. Validate a harness on one case before queueing a batch behind it

5c cost four generations rather than one because three runs were queued behind an
unvalidated script. One smoke case first would have caught it.

### 5e. Adding a measured quantity is two edits, not one

Twice, a term was added, applied correctly, and **never appeared in the
diagnostic table** — because a second hardcoded list of component names lived in
a different file. In one case the second-largest penalty in the budget was
invisible in every report produced for days.

Fix: after adding a term, `grep -rn` for a **sibling** term's name; every list
that enumerates the siblings needs the new one too.

### 5f. Determinism is a tool, not a curiosity

Training here is byte-identical given `(seed, config)`: two separately launched
runs produced identical `policy.pth` and `optimizer.pth`, differing only in the
metadata blob. Two uses:
- detect duplicated work (one 25-min run was a rediscovery of an existing arm);
- attribute scatter — if repeats are identical, observed spread is *within-run*,
  with no third source to hunt.

### 5g. An autonomous queue must never terminate into idle

Two driver chains ended by design "waiting for me to look at the frames". The
machine then sat idle **11 h**, and later about **45 h** — roughly 56 of the last
72 hours produced nothing.

This cost more than any single experimental mistake in the whole engagement.

Fix: a driver that always has the next generation queued, derives that
generation's config from the previous one's own outputs, and never exits into an
empty queue. Human review happens *alongside* a running queue, never as a gate
in front of one.

### 5h. Options that change an artifact's meaning belong in a manifest beside it

Execution-layer options (action band, command-bandwidth cap, slew clamp) must
accompany an artifact when it is evaluated. A mismatch does not raise — it reads
as a *failure of the artifact* (0.000 instead of 0.376), which is the worst
possible failure mode because it looks like a result.

Fix direction: write a per-artifact manifest at production time and have every
consumer read it back and refuse on mismatch.

### 5i. Verify at runtime what you are about to spend days on

Reading a mode off the source said one thing; two commands later, one run-time
probe said the friction actually sampled was something else. Cheap probes —
sample the value, print it, assert it — belong in front of any batch that will
run overnight.

## 6. Standing rules that came out of this

- **CLAUDE.md 6** — no AI attribution anywhere; verify before pushing.
- **CLAUDE.md 7** — confirm the branch; do not infer it from `HEAD`.
- **Naming rule** — never label a parameter value by species; the number only,
  in code, docs, plots and prose.
- **Fleet rules** — layout changes announced before pushing; every run tees to a
  committed log.
- **Engineering constraints** (already in CLAUDE.md, all earned):
  `gait_config` global setters do not restore; the floor friction priority hack
  is load-bearing; the μ stance gate differs between tools (`F_HI=4 N` vs
  `FN_MIN=1 N`) so μ numbers must not be mixed across them.
